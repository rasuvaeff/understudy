# rasuvaeff/understudy

> **Пре-релиз.** API не стабилен до `v0.1.0`. Что уже готово — в
> [CHANGELOG.md](CHANGELOG.md).

Библиотека тестовых дублей для PHP, где настраиваемый вызов — **настоящий
вызов**:

```php
when(fn () => $repository->find(123))->returns($book);
```

Никаких строк с именами методов: рефакторинг и навигация IDE работают без
плагина, а опечатка в имени метода невозможна. На самом дубле тоже нет
служебных методов — каждый из них отнимал бы имя у дублируемого контракта.

> Пользуетесь AI-ассистентом? [llms.txt](llms.txt) — компактный справочник по
> API, написанный для него.

## Зачем ещё одна

| | Understudy | Mockery / PHPUnit / double |
|---|---|---|
| Как задаётся вызов | настоящим вызовом в замыкании | строкой с именем метода |
| Служебные члены на дубле | нет | `shouldReceive`, `expects`, `allows`, … |
| Тестовый раннер | любой (тонкие адаптеры) | привязка к PHPUnit/Pest либо никакой |
| Fibers | свой контекст на файбер | общее статическое состояние |

Форма «вызов в замыкании» пришла из [MockK](https://mockk.io) (Kotlin),
[FakeItEasy](https://fakeiteasy.github.io) и [moq](https://github.com/moq/moq)
(C#), [mocktail](https://pub.dev/packages/mocktail) (Dart). В PHP её не было
ни у кого.

## Производительность

Против Mockery 1.6.15, Prophecy 1.26.1 и PHPUnit 12.5.33 на PHP 8.5.6. Медианы
после отсечения выбросов, understudy — база. Полная методика, сырые таблицы и
окружение — в [perf/README.md](perf/README.md).

| | understudy | Mockery | Prophecy | PHPUnit |
|---|---|---|---|---|
| создать дубль (контракт из 1 метода) | **2.08µs** | +355% | +1013% | +304%¹ |
| создать дубль (контракт из 8 методов) | **2.32µs** | +341% | +954% | +278%¹ |
| stub: создать, застабить, вызвать, снести | **14.7µs** | +45% | +125% | +27%¹ |
| mock: создать, expect, вызвать, verify | **18.0µs** | +30% | +175% | +16%² |
| предельная цена одного вызова к стабу | 1.75µs | 2.58µs | —³ | **1.08µs**¹ |
| добавляет к старту процесса (холодный) | **3.9ms** | 7.3ms | 16.5ms | 17.0ms |
| удерживает на каждый живой дубль | **~350 B** | 513 B | ~8.5 KB | ~1.25 KB |

¹ `createStub()` ² `createMock()` ³ не поддаётся цитированию — на пути вызова
Prophecy аллоцирует столько, что замеряется сборка мусора, а не сам вызов.

Understudy создаёт дубли примерно вчетверо дешевле ближайшего и удерживает
живой дубль в 1.5–25 раз меньшей памяти. Выигрывает он **не везде**: PHPUnit
диспетчеризует застабленный вызов за 1.08µs против 1.75µs у understudy, так что
после примерно тридцати вызовов к одному стабу дешевле оказывается тест на
PHPUnit.

Цифры информационные и ничего не гейтят. Перед тем как их где-то цитировать,
пересними их через `make perf`.

## Использование

### Создание дубля

```php
use Rasuvaeff\Understudy\Understudy;

$repository = Understudy::for(BookRepository::class);
```

`for()` возвращает тип самого контракта, поэтому IDE и статический анализатор
видят в `$repository` обычный `BookRepository`. Несколько интерфейсов
объединяются:

```php
$double = Understudy::for(BookRepository::class, Countable::class);
```

Совместимые сигнатуры этих интерфейсов объединяются: типы параметров
расширяются, возвращаемый тип берётся из самого узкого совместимого объявления
или синтезируется как пересечение интерфейсов, а имена named-аргументов — из
первого (основного) интерфейса. Статические методы контракта присутствуют в
сгенерированном классе, чтобы он мог реализовать интерфейс, но их вызов бросает
`InvalidCallSpecification`: у статического вызова нет экземпляра дубля,
которому принадлежало бы состояние.

Класс может быть первой целью, интерфейсы — после него:

```php
$repository = Understudy::for(DoctrineBookRepository::class, Countable::class);
```

Что дубль класса делает и чего не делает:

| | |
|---|---|
| конструктор цели | не вызывается — дубль строится без него, ни один побочный эффект конструирования в тест не попадает |
| public- и protected-методы | переопределяются и диспетчеризуются; protected виден в transcript и в strict-режиме, но нативная видимость PHP не пускает его в setup-замыкание |
| private- и static-методы | не трогаются — у них нет instance-состояния, которое можно перехватить |
| деструктор | заменяется пустым, чтобы не сносить то, что никогда не создавалось |
| записываемые public-свойства | стартуют с пустого значения своего типа; объектные, hooked, `final`, `readonly` и `private(set)` остаются неинициализированными, и чтение даёт нативную ошибку PHP |
| `clone` | даёт самостоятельный дубль: те же контракты, без ожиданий и без журнала вызовов, владелец — контекст, который клонировал |

`readonly`-цель даёт `readonly`-дубль — этого требует PHP, и это ничего не
стоит: собственных свойств дубль не объявляет.

Часть целей отвергается до генерации, каждая с причиной и указанием, что делать
вместо: `final`-класс, класс с non-private `final` instance-методом, enum,
trait, internal-класс, анонимный класс и любой класс не на первом месте. Дубль,
который не может перехватить все методы, исполнил бы настоящий код цели над
объектом с невыполненным конструктором — это хуже, чем не собраться вовсе.

Дефолты параметров воспроизводятся, а не приближаются: константа класса
рендерится через объявляющий класс, enum-case — как он есть, объектный дефолт —
из собственного исходного выражения (`new Stamp(7)` и `[new Stamp(7)]`
одинаково), которое при генерации ни разу не вычисляется. Дефолт, в исходнике
которого есть `self`, `static` или `parent`, отвергает цель: они резолвятся
против сгенерированного класса и ответили бы не тем, что обещает контракт.

### Дублирование final-класса

Чужой `final`-класс, интерфейса нет, поменять нельзя — ради этого случая и
существует `bypassFinals()`:

```php
// В bootstrap теста, до автозагрузки класса.
Understudy::bypassFinals(FinalGate::class);   // один класс
Understudy::bypassFinals();                    // все, что процесс загрузит дальше
```

Он opt-in, потому что у техники есть границы, и встретить их лучше осознанно,
чем обнаружить:

| | |
|---|---|
| Важен порядок | работает только для класса, ещё не прочитанного с диска; класс читается один раз на процесс |
| Процесс меняется | класс действительно перестаёт быть final, и рефлексия в тесте видит не то, что продакшен |
| `final`-методы остаются | такой метод не переопределить в любом случае, поэтому класс с ним по-прежнему отвергается |
| PHAR и preload | исходник приходит как `phar://` либо раньше любого bootstrap, поэтому через `file://`-враппер не проходит вовсе |
| Opcode-кэш не возвращает запечатанный класс | насколько бы тёплым кэш ни был и держит ли он bypass-нутый файл — Linux не держит, Windows держит — класс остаётся открытым. Отсутствие в кэше это цена там, где оно есть, а не гарантия, на которую стоит опираться |
| Чужой трансформер исходника | если PHP-исходник уже кто-то переписывает, understudy откажется, а не подменит молча; враппер, который исходник не трогает, композируется и принимается |

Если класс всё ещё final в момент `for()`, отказ говорит, какой именно это
случай — bypass не включали вовсе, включили для других классов, но не для
этого, или включили, но он не достал, — вместо того чтобы отправлять проверять
то, что и так в порядке.

По убыванию предпочтительности: дублировать интерфейс, который класс реализует;
для value object — собрать настоящий; ввести интерфейс. Bypass — ответ, когда
ничего из этого недоступно.

### Стабы

```php
use Rasuvaeff\Understudy\Arg;
use Rasuvaeff\Understudy\Invocation;

use function Rasuvaeff\Understudy\when;

when(fn () => $repository->find(123))->returns($book);
when(fn () => $repository->find(404))->throws(new NotFound());
when(fn () => $repository->find(Arg::any()))->answers(
    fn (Invocation $call) => new Book(title: (string) $call->args[0]),
);

// По значению на вызов, дальше повторяется последнее.
when(fn () => $repository->mode())->returns('fast', 'slow');
```

Более поздний стаб на тот же вызов выигрывает, а ранние остаются запасными —
поэтому широкий стаб с `Arg::any()` может лежать под точечным.

| Матчер | Что принимает |
|---|---|
| `Arg::any()` | что угодно, включая `null` |
| `Arg::int(min:, max:)` | `int` в диапазоне — числовая строка НЕ подходит |
| `Arg::float(min:, max:)` | `float` в диапазоне — `int` НЕ подходит |
| `Arg::string(matches:)` | строку, опционально по PCRE-шаблону |
| `Arg::bool()` | булево |
| `Arg::same($v)` | строгую идентичность; для объектов — тот же экземпляр |
| `Arg::not($v)` | отрицание литерала или другого матчера |
| `Arg::instanceOf($class)` | экземпляр класса или интерфейса |
| `Arg::satisfies($fn)` | то, что принимает предикат |
| `Arg::containing($entries)` | массив, содержащий эти элементы и, возможно, другие |
| `Arg::count(minimum:, maximum:)` | массив или `Countable` такого размера |
| `Arg::which($method, $value)` | объект, чей геттер отвечает этим значением |
| `Arg::none()` | пустой variadic-хвост — только последним аргументом |
| `Arg::remaining()` | весь variadic-хвост любой длины — только последним |

Типовые матчеры намеренно строгие: `Arg::int()` отвергает `'5'`, а
`Arg::float()` отвергает `1`. Матчер закрепляет объявленный тип не меньше, чем
значение, — ради этого он и нужен в коде со `strict_types`.

`Arg::which()` вызывает только публичный нестатический метод без обязательных
аргументов. Геттер, бросивший исключение, считается несовпадением, а не
ошибкой: сопоставление идёт во время работы тестируемого кода, и матчер не
должен быть тем, что его ломает.


### Ожидание вызова

```php
use function Rasuvaeff\Understudy\expect;

expect(fn () => $repository->save($book));            // ровно один раз
expect(fn () => $repository->count())->times(1, 3);   // диапазон

Understudy::verifyAll();
```

`expect()` заявляет, сколько раз вызов обязан произойти, а `verifyAll()` это
проверяет. Стаб `when()` — разрешение, а не заявление; `->times(2)` делает его
заявлением. `verifyAll(strictStubs: true)` дополнительно валит ни разу не
использованный стаб.

`returns()` при этом не обязателен: счёт и ответ — разные вещи, значение даёт
типобезопасный дефолт режима, а совпавшее ожидание удовлетворяет и строгий
дубль — вызов ведь ожидался.

В Pest есть свой глобальный `expect()` — импортируйте наш как `expect as
expectCall` либо зовите `Understudy::expect()`.

### Цепочки поведения

```php
when(fn () => $breaker->call($operation))
    ->returns('ok')
    ->then()->throws(new ConnectionLost());
```

Одно звено на вызов; когда цепочка кончается, последнее звено продолжает
отвечать.

### Проверки

```php
use function Rasuvaeff\Understudy\verify;

verify(fn () => $repository->save($book));                 // хотя бы раз
verify(fn () => $repository->save($book), times: 2);       // ровно дважды
verify(fn () => $repository->save($book), minimum: 2);     // без верхней границы
verify(fn () => $repository->ping(), never: true);

Understudy::unused($repository);                           // вообще ни разу
```

Каждый дубль пишет все вызовы, поэтому проверку не нужно готовить заранее.

### Всё ли описано?

```php
Understudy::nothingElse($repository);   // все вызовы учтены
Understudy::allVerified($repository);   // ожидания выполнены И больше ничего не было
Understudy::verifySequence(             // точный протокол, через все дубли
    fn () => $repository->begin(),
    fn () => $repository->save($book),
    fn () => $repository->commit(),
);
```

Вызов считается учтённым, если его сматчило `expect()` либо его заявил
**успешный** `verify()`. Стаб `when()` не учитывает ничего — он разрешение, а
не описание произошедшего; упавший `verify()` тоже ничего не учитывает.

`expect(...)->ordered()` связывает упорядоченные ожидания между собой;
посторонние вызовы между ними допустимы. Когда важен весь протокол целиком —
это `verifySequence()`. Он сравнивает не только метод и аргументы, но и сам
экземпляр дубля, даже если несколько дублей реализуют один контракт.
`allVerified()` также проверяет порядок ожиданий.

### Фазы, области и транскрипт

```php
Understudy::checkpoint();                       // проверить и забыть завершённое
$result = Understudy::scope(fn () => ...);      // вложенный контекст, проверяемый при успехе
echo Understudy::transcript($repository);       // все вызовы и их исходы
```

`scope()` возвращает то, что вернул колбэк, и в любом случае сбрасывает
вложенный контекст — ошибка внутри никогда не подменяется ошибкой очистки.
Созданный в области дубль после её закрытия недействителен. Настраивать и
проверять дубль можно только в контексте-владельце; обычный вызов допустим из
другого Fiber и всё равно записывается в лог владельца.
`checkpoint()` сохраняет дубли, их режимы и метки, очищая то, что текущая фаза
уже завершила.

### Чтение лога вызовов

```php
use Rasuvaeff\Understudy\Arg;

$calls = Understudy::calls(fn () => $repository->find(Arg::any()));

$calls[0]->args;          // [123]
$calls[0]->didReturn();   // true
$calls[0]->returned();    // чем ответил
$calls[1]->thrown();      // исключение, если бросил
```

`null` — полноценное возвращаемое значение, поэтому об исходе спрашивают
(`didReturn()`), а не выводят его из самого значения.

### Режимы

| Режим | Чем отвечает несовпавший вызов |
|---|---|
| Loose (по умолчанию) | типобезопасным значением: `null`, `0`, `''`, `[]`, пустой генератор … |
| Strict (`Understudy::strict($double)`) | немедленной ошибкой с именем метода |
| Forwarding (`Understudy::forwarding($double, $real)`) | тем, что ответит реальный инстанс — с записью вызова, как любого другого |

Loose-дубль никогда не выдумывает значение, запуская чужой конструктор, и
никогда не отдаёт экземпляр настоящего класса с пропущенным конструктором.
Отдать он может другой дубль: возвращаемый тип, который сам можно дублировать,
становится дублем — на один уровень, и тот же тест может его настроить. Это
сгенерированный заменитель, а не цель с пропущенным конструктором.

Ровно один уровень: созданный так дубль откажется породить следующий, поэтому
`$a->b()->c()` скажет об этом, а не выдумает третью зависимость, о которой тест
не просил. Зарегистрировать фабрику для `C` — способ сказать, что вы этого
хотели. Если безопасного значения нет — он говорит об этом и подсказывает выход.

### Как сказать, каким должен быть дефолт

Вложенный дубль `LoggerInterface` отвечает на всё дефолтами и не сообщает тесту
ничего. Обычно нужен `NullLogger`:

```php
Understudy::defaults(LoggerInterface::class, fn () => new NullLogger());
Understudy::defaults(ClockInterface::class, fn () => FakeClock::frozen());
```

Побеждает ближайшая регистрация — по расстоянию в графе типов: сначала точное
совпадение, затем ближайший зарегистрированный предок. Два предка на одинаковом
расстоянии дают `AmbiguousDefaultFactory`, а не «кто раньше зарегистрировался» —
у ничьей нет порядка, который читатель мог бы предсказать. Фабрика, вернувшая не
тот тип, даёт `InvalidDefaultValue`.

Регистрации принадлежат текущему контексту: соседние Fiber'ы не видят чужих, а
`Understudy::reset()` удаляет их вместе с тестом. Регистрировать их следует в
per-test фикстуре, а не один раз на весь suite.

### Сборка тестируемого объекта

```php
['sut' => $service, 'doubles' => $d] = Understudy::wire(CatalogService::class);

/** @var Repository $repository */
$repository = $d['repository'];
when(fn () => $repository->find(1))->returns($book);

Assert::same($service->lookup(1), $book);
```

`wire()` читает конструктор и больше ничего: ни контейнера, ни инъекции в
свойства, ни сеттеров. Юнит-тесту важны те зависимости, о которых класс просит
сам.

| Параметр конструктора | Что получает |
|---|---|
| класс или интерфейс | дубль, попадает в `doubles` под именем параметра |
| nullable-объект | дубль — `null` тест может попросить явно |
| пересечение типов | один дубль обоих контрактов |
| union из нескольких объектных типов | отказ: выбрать один значило бы угадать |
| объект, который нельзя дублировать, с дефолтом | собственный дефолт, применённый PHP |
| скаляр с дефолтом | объявленный дефолт, без дубля |
| скаляр без дефолта | отказ с указанием, какой override передать |
| вариадический хвост | остаётся пустым; выдумать элементы значило бы выдумать зависимости |
| параметр по ссылке | отказ — override'ы это значения, и передать их значило бы пообещать reference-семантику, которой у `wire()` нет |

`overrides: ['name' => $value]` подменяет одну зависимость реальным объектом или
готовым дублем; они уже у вас в руках, поэтому в `doubles` не попадают. Любой
отказ происходит до вызова конструктора — неверный тип сообщает `wire()`, а не
`TypeError` изнутри тестируемого объекта.

Вариадический хвост принимает список, и каждый элемент проверяется против
объявленного типа до вызова конструктора:

```php
['sut' => $service] = Understudy::wire(TaggedService::class, ['tags' => ['a', 'b']]);
```

Всё, что не список — голое значение, массив со строковыми ключами, — отвергается
с указанием имени, как и элемент неверного типа. Заполнение хвоста означает, что
параметры перед ним передаются позиционно, поэтому пропущенный опциональный
параметр получает материализованный объявленный дефолт; это единственное место,
где `wire()` вычисляет дефолт сам, а не оставляет его PHP.

### Делегирование реальному объекту

```php
$real = $container->get(CacheInterface::class);
$spy = Understudy::for(CacheInterface::class);
Understudy::forwarding($spy, $real);

when(fn () => $spy->get('key'))->throws(new PoolOverload());
```

Всё, что тест не настроил, выполняется по-настоящему и записывается; `get('key')`
бросает. Инстанс обязан удовлетворять всем контрактам дубля, иначе отвергается.

`Understudy::for($real)` — сокращение для не-final класса: строит дубль класса
этого объекта и запоминает сам объект, но продолжает отвечать дефолтами, пока
`Understudy::forwarding($double)` не включит делегирование. Обернуть — не то же
самое, что делегировать. Final-класс отвергается: он уже загружен, и дубль не
сможет сохранить конкретный тип, который вы держите в руках.

Внутри ответа один вызов можно пропустить наружу:

```php
when(fn () => $spy->get('key'))
    ->answers(fn (Invocation $call) => strtoupper((string) $call->callOriginal()));
```

Пять вещей, которые стоит знать заранее:

- **Записывается только вызов на границе.** Если реальный метод зовёт другой
  метод на себе, это происходит внутри реального объекта. Understudy проксирует
  объект, а не инструментирует его.
- **Метод с `: never` доходит до реальной реализации.** Бросок живёт именно
  там, а у forwarding-дубля есть кому ответить за себя.
- **Дубль не может быть целью.** Делегирование дублю — в том числе самому себе —
  возвращает каждый вызов обратно в диспетчер, и несовпавший будет возвращаться,
  пока не кончится стек.
- **Аргумент по ссылке — это переменная вызывающего.** Форвардящийся метод в
  неё пишет, и журнал хранит оба чтения — что передали и чем оно стало, — так
  что проверка по-прежнему видит значение, которое отдал вызывающий.
- **Fluent-метод возвращается дублем.** Когда реальный инстанс вернул сам себя,
  наружу уходит дубль — цепочка остаётся дублированной. Метод с `static`,
  вернувший *другой* экземпляр реального класса, отвергается: этот объект не
  дубль, и вернуть его значило бы нарушить собственный `: static` переопределения.

### Сообщения об ошибках

```text
Understudy `BookRepository` expected `tag('alpha', 2)` to be called exactly 1 time,
but it was never called.

The following calls to `tag` were made during this test:
    tag(*'beta'*, 2)
```

Звёздочками помечен разошедшийся аргумент — приём заимствован у
[NSubstitute](https://nsubstitute.github.io). `Understudy::label($double, '…')`
даёт дублю имя, когда их в тесте несколько на один контракт.

### Очистка

```php
Understudy::reset();
```

Адаптеры для Testo и PHPUnit будут вызывать это сами; пока их нет — вызывайте
в своём teardown. Reset очищает только текущий execution context и не стирает
контексты соседних Fiber.

## Безопасность

Understudy генерирует по классу на набор контрактов и вычисляет его один раз
за процесс. Она не загружает код из пользовательского ввода, не обращается к
файловой системе и держит всё состояние в `WeakMap` по ключу-объекту — а не по
`spl_object_id()`, который PHP переиспользует после сборки мусора.

Это dev-зависимость. В production её ставить не нужно.

```bash
make build          # validate, normalize, require-checker, cs, psalm, test
make cs-fix
make psalm
make test
make mutation       # infection, гейт 85% MSI
make release-check

make perf-install   # один раз: сравнительный харнесс в perf/

make perf-cold      # холодный старт, один процесс на дубль
make perf-memory    # память на живой дубль
```

Или напрямую через Docker:

```bash
docker run --rm -v "$PWD":/app -w /app composer:2 composer build
```

В `spikes/` лежат feasibility-фикстуры, на которых стоит дизайн; `bash
spikes/run.sh` прогоняет их на любом PHP 8.3+.
