**Документация:** <https://rasuvaeff.github.io/understudy/> — руководство,
гайды миграции с Mockery и PHPUnit, cookbook реальных инцидентов и
сгенерированный API-справочник по всем пяти пакетам. Сайт на английском.

Библиотека тестовых дублей для PHP, где настраиваемый вызов — **настоящий
вызов**:

```php
when(fn () => $repository->find(123))->returns($book);
```

Никаких строк с именами методов: рефакторинг и навигация IDE работают без
плагина, а опечатка в имени метода невозможна. На самом дубле тоже нет
служебных методов — каждый из них отнимал бы имя у дублируемого контракта.

> Пользуетесь AI-ассистентом? [llms.txt](llms.txt) — компактный справочник по
> API, написанный для него.

## Зачем ещё одна

| | Understudy | Mockery / PHPUnit / double |
|---|---|---|
| Как задаётся вызов | настоящим вызовом в замыкании | строкой с именем метода |
| Служебные члены на дубле | нет | `shouldReceive`, `expects`, `allows`, … |
| Тестовый раннер | любой (тонкие адаптеры) | привязка к PHPUnit/Pest либо никакой |
| Fibers | свой контекст на файбер | общее статическое состояние |

Форма «вызов в замыкании» пришла из [MockK](https://mockk.io) (Kotlin),
[FakeItEasy](https://fakeiteasy.github.io) и [moq](https://github.com/moq/moq)
(C#), [mocktail](https://pub.dev/packages/mocktail) (Dart). В PHP её не было
ни у кого.

## Миграция с Mockery

Ни алиасов, ни конвертера — таблица переводит знакомый глагол в здешнюю форму.
Две строки — ловушки, помечены ⚠.

| Mockery | Understudy | Примечание |
|---|---|---|
| `Mockery::mock(BookRepository::class)` | `Understudy::for(BookRepository::class)` | |
| `$mock->shouldReceive('find')` | `when(fn () => $mock->find(...))` | настоящий вызов; без строки с именем метода |
| `->once()` / `->twice()` / `->times(3)` | `expect(fn () => ...)->times(3)` | `expect()` проверяется `verifyAll()` или адаптером |
| `->atLeast()->once()` | `expect(...)->times(1, null)` | |
| `->andReturn($book)` | `->returns($book)` | |
| `->andReturnUsing(fn ...)` | `->answers(fn (Invocation $i) => ...)` | аргументы — из `$i->args` |
| `->andThrow(new NotFound())` | `->throws(new NotFound())` | |
| `->with(123, Mockery::any())` | в замыкании: `find(123, Arg::any())` | |
| `Mockery::on(fn ($x) => ...)` | `Arg::satisfies(fn ($x) => ...)` | |
| `$mock->shouldNotHaveReceived('save')` | `Understudy::unused($mock)` | |
| `$mock->shouldHaveReceived('save')` | `verify(fn () => $mock->save(...))` | пост-фактум; добавьте `nothingElse()` — см. ниже |
| `Mockery::close()` | reset() адаптера или свой teardown | |
| `->makePartial()` / `Mockery::spy($real)` | `Understudy::delegate(Contract::class, $real)` + стабы поверх | стаб побеждает, остальное выполняется по-настоящему — и записывается |
| `->withAnyArgs()` | в замыкании: `method(Arg::rest())` | а ещё спасение от широкой сигнатуры: `method('svc', Arg::rest())` |
| `Mockery::capture($x)` | `Arg::captor(X::class)` + `$captor->capture()` | `last()`/`all()` типизированы через class-string — без `instanceof` на чтении |
| ⚠ `->shouldReceive(...)->once()` как setup | `when(...)->returns(...)` | `when()` — разрешение, а не утверждение: если нужно было только значение, `expect()` превратит случайную настройку в падающий тест |
| ⚠ шпион со счётчиком всех вызовов | `expect()` + `Understudy::nothingElse($mock)` | `expect()` считает только вызовы под **своими** аргументами; без `nothingElse()` второй вызов с другими аргументами проходит — рукописный счётчик это ловил, миграция не должна это терять |

## Производительность

Против Mockery 1.6.15, Prophecy 1.26.1 и PHPUnit 12.5.33 на PHP 8.5.6.
Фильтрованные средние, три прогона, understudy — база. Полная методика, сырые
таблицы и окружение — в [perf/README.md](perf/README.md).

| | understudy | Mockery | Prophecy | PHPUnit |
|---|---|---|---|---|
| создать дубль (контракт из 1 метода) | **2.06µs** | +216% | +683% | +155%¹ |
| создать дубль (контракт из 8 методов) | **2.06µs** | +217% | +641% | +158%¹ |
| stub: создать, застабить, вызвать, снести | 10.6µs | +17% | +76% | **−17%**¹ |
| mock: создать, expect, вызвать, verify | 12.8µs | +4% | +128% | **−27%**² |
| предельная цена одного вызова к стабу | 0.86µs | 1.61µs | 1.51µs | **0.69µs**¹ |
| добавляет к старту процесса (холодный) | **1.00×** | 1.50× | 4.96× | 5.38׳ |
| удерживает на каждый живой дубль | **467–482 B** | 513 B | ~8.5 KB | ~1.25 KB |

¹ `createStub()` ² `createMock()` ³ отношение, а не миллисекунды: холодный
старт разбегается между прогонами куда сильнее, чем его отношения.

Understudy создаёт дубли примерно в два с половиной раза дешевле ближайшего и
добавляет к старту процесса впятеро меньше. Выигрывает он **не везде**:
PHPUnit впереди и на stub-, и на mock-сценарии целиком — он диспетчеризует
вызов за 0.69µs против 0.86µs у understudy и больше не платит на создании
столько, чтобы это перекрыть.

**Создание дубля стоит дороже, чем раньше** — 2.06µs против 1.28µs в цифрах,
опубликованных с 0.1.x. Те цифры сняты на коммите *до* 0.1.0 и не описывали ни
одну выпущенную версию: между ними и первым тегом приехала регрессия, которая с
тех пор и отгружается. Она локализована бисектом и описана в
[perf/README.md](perf/README.md); попытка её убрать перенесла цену в другое
место и была откачена.

Цифры информационные и ничего не гейтят. Перед тем как их где-то цитировать,
пересними их через `make perf`.

## Требования

- PHP 8.3 – 8.5
- `ext-tokenizer`

Больше никаких runtime-зависимостей (`ext-mbstring` не нужен — символы в
сообщениях об ошибках считает PCRE, который отключить нельзя).

## Использование

### Создание дубля

```php
use Rasuvaeff\Understudy\Understudy;

$repository = Understudy::for(BookRepository::class);
```

`for()` возвращает тип самого контракта, поэтому IDE и статический анализатор
видят в `$repository` обычный `BookRepository`. Несколько интерфейсов
объединяются:

```php
$double = Understudy::for(BookRepository::class, Countable::class);
```

Совместимые сигнатуры этих интерфейсов объединяются: типы параметров
расширяются, возвращаемый тип берётся из самого узкого совместимого объявления
или синтезируется как пересечение интерфейсов, а имена named-аргументов — из
первого (основного) интерфейса. Статические методы контракта присутствуют в
сгенерированном классе, чтобы он мог реализовать интерфейс, но их вызов бросает
`InvalidCallSpecification`: у статического вызова нет экземпляра дубля,
которому принадлежало бы состояние.

Класс может быть первой целью, интерфейсы — после него:

```php
$repository = Understudy::for(DoctrineBookRepository::class, Countable::class);
```

Что дубль класса делает и чего не делает:

| | |
|---|---|
| конструктор цели | не вызывается — дубль строится без него, ни один побочный эффект конструирования в тест не попадает |
| public- и protected-методы | переопределяются и диспетчеризуются; protected виден в transcript и в strict-режиме, но нативная видимость PHP не пускает его в setup-замыкание |
| private- и static-методы | не трогаются — у них нет instance-состояния, которое можно перехватить |
| деструктор | заменяется пустым, чтобы не сносить то, что никогда не создавалось |
| записываемые public-свойства | стартуют с пустого значения своего типа; объектные, hooked, `final`, `readonly` и `private(set)` остаются неинициализированными, и чтение даёт нативную ошибку PHP |
| `clone` | даёт самостоятельный дубль: те же контракты, без ожиданий и без журнала вызовов, владелец — контекст, который клонировал |

`readonly`-цель даёт `readonly`-дубль — этого требует PHP, и это ничего не
стоит: собственных свойств дубль не объявляет.

Часть целей отвергается до генерации, каждая с причиной и указанием, что делать
вместо: `final`-класс, класс с non-private `final` instance-методом, enum,
trait, internal-класс, анонимный класс и любой класс не на первом месте. Дубль,
который не может перехватить все методы, исполнил бы настоящий код цели над
объектом с невыполненным конструктором — это хуже, чем не собраться вовсе.

### Property hooks (PHP 8.4+)

Контракт, объявляющий свойство, дублируется:

```php
interface Customer
{
    public string $name { get; }
    public Money $balance { get; set; }
}

$customer = Understudy::for(Customer::class);
$customer->name;      // типобезопасный дефолт режима: ''
$customer->balance;   // depth-1 дубль Money либо ваша регистрация defaults()
```

Ни одна `__get`-библиотека так не может: `__get` срабатывает только для
*недоступного* свойства — ровно не наш случай, когда контракт его объявляет.
Understudy генерирует исходник класса, поэтому объявляет свойство и ставит
диспетчер внутрь хука. Рендерятся ровно объявленные хуки: get-only свойство
отвергает запись ошибкой самого PHP. Чтение отвечает, по порядку: значением
реального инстанса на forwarding-дубле, тем, что тестируемый код записал
раньше (`{ get; set; }` ведёт себя как обычное свойство), и иначе — той же
таблицей дефолтов, что и возврат метода, включая регистрации
`Understudy::defaults()` и depth-1 вложенный дубль.

Чтение свойства — **не вызов**: оно не записывается, не специфицируется через
`when()`/`expect()` и не судится strict-режимом — тот же статус, что уже есть
у обычного публичного свойства на дубле класса. `clone` дубля записанные
значения свойств не переносит: копия — самостоятельный дубль, здесь как и
везде. Два случая по-прежнему
отвергаются с причиной: `readonly`-класс-цель, чей контракт несёт абстрактный
хук (readonly-класс расширяется только readonly-классом, а hooked-свойство не
может быть readonly), и `&get`-хук по ссылке. Конкретный хук на классе-цели
наследуется и продолжает исполнять код цели.

Дефолты параметров воспроизводятся, а не приближаются: константа класса
рендерится через объявляющий класс, enum-case — как он есть, объектный дефолт —
из собственного исходного выражения (`new Stamp(7)` и `[new Stamp(7)]`
одинаково), которое при генерации ни разу не вычисляется. Дефолт, в исходнике
которого есть `self`, `static` или `parent`, отвергает цель: они резолвятся
против сгенерированного класса и ответили бы не тем, что обещает контракт.

### Дублирование final-класса

Чужой `final`-класс, интерфейса нет, поменять нельзя — ради этого случая и
существует `bypassFinals()`:

```php
// В bootstrap теста, до автозагрузки класса.
Understudy::bypassFinals(FinalGate::class);   // один класс
Understudy::bypassFinals();                    // все, что процесс загрузит дальше
```

Он opt-in, потому что у техники есть границы, и встретить их лучше осознанно,
чем обнаружить:

| | |
|---|---|
| Важен порядок | работает только для класса, ещё не прочитанного с диска; класс читается один раз на процесс |
| Процесс меняется | класс действительно перестаёт быть final, и рефлексия в тесте видит не то, что продакшен |
| `final`-методы остаются | такой метод не переопределить в любом случае, поэтому класс с ним по-прежнему отвергается |
| PHAR и preload | исходник приходит как `phar://` либо раньше любого bootstrap, поэтому через `file://`-враппер не проходит вовсе |
| Opcode-кэш не возвращает запечатанный класс | насколько бы тёплым кэш ни был и держит ли он bypass-нутый файл — Linux не держит, Windows держит — класс остаётся открытым. Отсутствие в кэше это цена там, где оно есть, а не гарантия, на которую стоит опираться |
| Чужой трансформер исходника | если PHP-исходник уже кто-то переписывает, understudy откажется, а не подменит молча; враппер, который исходник не трогает, композируется и принимается |

Если класс всё ещё final в момент `for()`, отказ говорит, какой именно это
случай — bypass не включали вовсе, включили для других классов, но не для
этого, или включили, но он не достал, — вместо того чтобы отправлять проверять
то, что и так в порядке.

По убыванию предпочтительности: дублировать интерфейс, который класс реализует;
для value object — собрать настоящий; ввести интерфейс. Bypass — ответ, когда
ничего из этого недоступно.

### Стабы

```php
use Rasuvaeff\Understudy\Arg;
use Rasuvaeff\Understudy\Invocation;

use function Rasuvaeff\Understudy\when;

when(fn () => $repository->find(123))->returns($book);
when(fn () => $repository->find(404))->throws(new NotFound());
when(fn () => $repository->find(Arg::any()))->answers(
    fn (Invocation $call) => new Book(title: (string) $call->args[0]),
);

// По значению на вызов, дальше повторяется последнее.
when(fn () => $repository->mode())->returns('fast', 'slow');
```

Более поздний стаб на тот же вызов выигрывает, а ранние остаются запасными —
поэтому широкий стаб с `Arg::any()` может лежать под точечным.

| Матчер | Что принимает |
|---|---|
| `Arg::any()` | что угодно, включая `null` |
| `Arg::int(min:, max:)` | `int` в диапазоне — числовая строка НЕ подходит |
| `Arg::float(min:, max:)` | `float` в диапазоне — `int` НЕ подходит |
| `Arg::string(matches:)` | строку, опционально по PCRE-шаблону |
| `Arg::bool()` | булево |
| `Arg::same($v)` | строгую идентичность; для объектов — тот же экземпляр |
| `Arg::not($v)` | отрицание литерала или другого матчера |
| `Arg::allOf(...)` | всё, что принимают все операнды; операнд — матчер или литерал |
| `Arg::anyOf(...)` | то, что принимает хотя бы один операнд: `anyOf('draft', 'review')` читается как множество |
| `Arg::instanceOf($class)` | экземпляр класса или интерфейса |
| `Arg::satisfies($fn)` | то, что принимает предикат |
| `Arg::containing($entries)` | массив, содержащий эти элементы и, возможно, другие |
| `Arg::count(minimum:, maximum:)` | массив или `Countable` такого размера |
| `Arg::which($method, $value)` | объект, чей геттер отвечает этим значением |
| `Arg::none()` | пустой variadic-хвост — только последним аргументом |
| `Arg::remaining()` | весь variadic-хвост любой длины — только последним |
| `Arg::rest()` | объявленные параметры, оставленные неназванными — только последним |

`Arg::rest()` и `Arg::remaining()` отвечают за разное: `remaining()` матчит
variadic-хвост, который метод объявляет, а `rest()` говорит «аргументы до меня
важны, остальная арность — нет» — это единственный матчер, позволяющий
спецификации остановиться до того, как закончатся обязательные параметры
метода:

```php
when(fn () => $storage->recordOutcome('svc', Arg::rest()))
    ->throws(new RuntimeException('storage unavailable'));
```

Спецификация, остановившаяся раньше *без* `Arg::rest()` в конце, отвергается с
объяснением — вместо того чтобы стать стабом, который молча никогда не
совпадёт. Более поздняя узкая спецификация того же вызова по-прежнему
побеждает широкий префиксный стаб. Один нюанс: статанализатор читает
укороченный вызов против арности контракта и сообщит «too few arguments» на
этой строке, пока не знает идиому.

Типовые матчеры намеренно строгие: `Arg::int()` отвергает `'5'`, а
`Arg::float()` отвергает `1`. Матчер закрепляет объявленный тип не меньше, чем
значение, — ради этого он и нужен в коде со `strict_types`.

Матчер, который не смог бы совпасть ни с чем, отвергается там, где написан, а
не проваливает ожидание в teardown: `Arg::int(min: 5, max: 1)` и его собратья
`float`/`count` описывают пустой диапазон, а `Arg::string('/[unclosed')` — не
компилируемый PCRE-паттерн, который вдобавок поднимал бы warning внутри
тестируемого кода на каждом вызове.

`Arg::which()` вызывает только публичный нестатический метод без обязательных
аргументов. Геттер, бросивший исключение, считается несовпадением, а не
ошибкой: сопоставление идёт во время работы тестируемого кода, и матчер не
должен быть тем, что его ломает.

### Захват аргумента

`Arg::captor()` — типизированная замена чтению `args[N]` из лога вызовов: без
позиционного индекса, без `mixed`, без ритуала сужения через `instanceof`:

```php
$options = Arg::captor(DeliveryOptions::class);      // Captor<DeliveryOptions>
when(fn () => $store->temporaryUrl(Arg::any(), Arg::any(), $options->capture()))
    ->returns('https://…');

$subject->run();

$options->last()->downloadName;   // типизировано: DeliveryOptions
$options->all();                  // list<DeliveryOptions>, в порядке вызовов
```

`capture()` ставится туда, где идёт наблюдаемый аргумент. Типизированная форма
матчит как `Arg::instanceOf()`, голый `Arg::captor()` — как `Arg::any()`, а
значение записывается только когда совпала **вся** спецификация: вызов,
отвергнутый другими аргументами, не захватывает ничего. Работает одинаково в
`when()`, `expect()` и `verify()`; `verify()` захватывает из вызовов, которые
только что подтвердил, — прочтение Mockito. `capture()` в шаге
`expectSequence()` совпадает, но не записывает — захватывайте при объявлении
или при верификации, не в протоколе. `last()` у пустого каптора бросает
`NothingCaptured`; `all()` отвечает пустым списком. Захваченные значения живут
ровно столько же, сколько лог вызовов: `reset()` и закрывающийся
`Understudy::scope()` сбрасывают их, каптор после этого просто снова пуст.


### Ожидание вызова

```php
use function Rasuvaeff\Understudy\expect;

expect(fn () => $repository->save($book));            // ровно один раз
expect(fn () => $repository->count())->times(3);      // ровно три раза
expect(fn () => $repository->count())->times(0);      // ни разу
expect(fn () => $repository->count())->times(1, 3);   // диапазон
expect(fn () => $repository->count())->times(2, null); // не меньше двух

Understudy::verifyAll();
```

`times()` смотрит на **число переданных** аргументов, поэтому один аргумент —
всегда точный счёт, как бы он ни был написан: `times(minimum: 2)` — это
`times(2)`, а не открытый диапазон. Для диапазона пишите второй аргумент.

`expect()` заявляет, сколько раз вызов обязан произойти, а `verifyAll()` это
проверяет. Стаб `when()` — разрешение, а не заявление; `->times(2)` делает его
заявлением. `verifyAll(strictStubs: true)` дополнительно валит ни разу не
использованный стаб.

`returns()` при этом не обязателен: счёт и ответ — разные вещи, значение даёт
типобезопасный дефолт режима, а совпавшее ожидание удовлетворяет и строгий
дубль — вызов ведь ожидался.

Стаб и ожидание на **в точности один и тот же вызов** не складываются — оба
порядка отклоняются при регистрации с `ConflictingExpectation`: что объявлено
позже, то забрало бы диспатч, молча выбросив ответ стаба или заморив счёт
ожидания. Скажите обе вещи об одном вызове одной регистрацией —
`expect(...)->returns(...)` либо `when(...)->times(...)`, а повторный счёт
объявляйте один раз через `times()`. Пересечение — не совпадение: широкий
запасной стаб под более узким ожиданием остаётся документированной слоёнкой.

Более поздний стаб на тот же вызов выигрывает, а ранние остаются запасными при
несовпадении аргументов. Ожидание с исчерпанным счётом продолжает отвечать на
совпавший вызов, поэтому для последующих вызовов с широким fallback используйте
непересекающийся матчер.

В Pest есть свой глобальный `expect()` — импортируйте наш как `expect as
expectCall` либо зовите `Understudy::expect()`.

### Цепочки поведения

```php
when(fn () => $breaker->call($operation))
    ->returns('ok')
    ->then()->throws(new ConnectionLost());
```

Одно звено на вызов; когда цепочка кончается, последнее звено продолжает
отвечать.

### Проверки

```php
use function Rasuvaeff\Understudy\verify;

verify(fn () => $repository->save($book));                 // хотя бы раз
verify(fn () => $repository->save($book), times: 2);       // ровно дважды
verify(fn () => $repository->save($book), minimum: 2);     // без верхней границы
verify(fn () => $repository->ping(), never: true);

Understudy::unused($repository);                           // вообще ни разу
```

Каждый дубль пишет все вызовы, поэтому проверку не нужно готовить заранее.

### Всё ли описано?

```php
Understudy::nothingElse($repository);   // все вызовы учтены
Understudy::nothingElse($repository, $clock, $mailer);   // сразу по нескольким дублям
Understudy::allVerified($repository);   // ожидания выполнены И больше ничего не было
Understudy::verifySequence(             // точный протокол, через все дубли
    fn () => $repository->begin(),
    fn () => $repository->save($book),
    fn () => $repository->commit(),
);
```

Вызов считается учтённым, если его сматчило `expect()` либо его заявил
**успешный** `verify()`. Стаб `when()` не учитывает ничего — он разрешение, а
не описание произошедшего; упавший `verify()` тоже ничего не учитывает.
`nothingElse()` принимает любое число дублей: одна строка закрывает весь тест,
а в сообщении об ошибке назван каждый нарушитель, а не только первый.

`expect(...)->ordered()` связывает упорядоченные ожидания между собой;
посторонние вызовы между ними допустимы. Когда важен весь протокол целиком —
это `verifySequence()`. Он сравнивает не только метод и аргументы, но и сам
экземпляр дубля, даже если несколько дублей реализуют один контракт.
`allVerified()` также проверяет порядок ожиданий.

### Падение на том вызове, который сломал порядок

Оба инструмента выше ретроспективны: исключение поднимается в teardown, и стек
указывает на `verifyAll()`, а не на вызов, ушедший не в свой черёд.
`expectSequence()` армирует протокол **до** запуска тестируемого кода, поэтому
отказ происходит внутри виновного вызова, и на вершине стека — кадр самого
субъекта:

```php
Understudy::expectSequence(
    fn () => $repository->begin(),
    fn () => $repository->save($book),
    fn () => $repository->commit(),
);

$service->handle($command);   // падает здесь, на сломавшем порядок вызове
```

```text
Understudy `BookRepository` received a protocol call out of turn: step 2 of 3 was expected to be `save(App\Book#1 {title: 'Dune'})`.

The call was:
    commit()

The protocol is:
    1. begin()
    2. save(App\Book#1 {title: 'Dune'})   <- due here
    3. commit()
```

| | |
|---|---|
| **Границы** | дубли, названные в протоколе. Дубль, которого он не называет, для него не существует |
| **На названном дубле** | вызов — либо текущий шаг, либо то, что тест настроил; всё остальное отвергается |
| **Каждый шаг** | ровно один раз, по порядку. Для относительного порядка, терпящего повторы, есть `ordered()` |
| **Незавершённость** | армирование — ещё и claim: `verifyAll()` доложит шаги, до которых субъект не дошёл |
| **Одновременно один** | армировать второй протокол, пока идёт первый, запрещено; завершённый можно заменить |
| **`checkpoint()`** | проверяет протокол вместе со всем остальным и сбрасывает — он принадлежит объявившей его фазе |

Цена второй строки осознанная: попутный запрос субъекта между шагами —
`$repository->find(7)` между `begin` и `save` — придётся застабить через
`when()`. Без этого протокол не отличит «это не его дело» от «вы перепутали
порядок», а догадка вернула бы падение в teardown — ровно туда, откуда
армирование уводит.

Субъект с широким `catch` может проглотить отказ. Именно поэтому армирование —
не только страж, но и claim: тест всё равно упадёт, в teardown, с указанием
шага, на котором он встал.

### Фазы, области и транскрипт

```php
Understudy::checkpoint();                       // проверить и забыть завершённое
$result = Understudy::scope(fn () => ...);      // вложенный контекст, проверяемый при успехе
echo Understudy::transcript($repository);       // все вызовы и их исходы
Understudy::idle();                             // true, если в контексте нет дублей
```

`transcript()` хранит каждый вызов до `reset()` или `checkpoint()`. Не
используйте дубль в неограниченном горячем цикле, если аргументы или ответы
удерживают большие графы объектов; для нагрузочных сценариев лучше fake.

Удержание распространяется на **возвращённые значения**, а `reset()` у
раннер-адаптеров выполняется *после* вашего `#[AfterTest]`/`tearDown()` — то
есть значение, которое дубль вернул, всё ещё удерживается, пока идёт ваш
teardown. Для обычных данных это только память; для значения, владеющего
OS-ресурсом — стрим, соединение, лок, — ресурс всё ещё занят. Конкретный
провал, который это даёт: forwarding-дубль возвращал настоящие файловые
стримы, и удаление каталога в teardown падало с «Directory not empty» — только
на Windows, потому что POSIX удаляет открытые файлы и все Linux-прогоны были
зелёными. Два средства:

```php
Understudy::lean($double);                       // хранить вызовы, но не возвращённые значения
$result = Understudy::scope(fn () => ...);       // либо сбросить весь контекст раньше
```

`lean()` сохраняет сам вызов — метод, аргументы, порядковый номер, — так что
матчинг, `verify()`, `transcript()` и `nothingElse()` работают как раньше, но
возвращённое значение не удерживается: `Invocation::returned()` бросает
`OutcomeUnavailable`, как уже делает для вызова, который бросил исключение, а
transcript показывает `returned (value not kept: lean)`. Это односторонний
переключатель на всю жизнь дубля; заодно он ограничивает рост памяти на вызов
в горячем цикле. Единственное, что `lean()` освободить не может, — стабильный
слот за `&`-возвратом: вызывающие держат живую ссылку внутрь него, и язык
требует, чтобы хранилище пережило вызов. Дубль, чьи возвращаемые значения владеют OS-ресурсами,
стройте lean — либо стройте и используйте внутри `Understudy::scope()`,
который сбрасывает контекст вместе с исходами до lifecycle-teardown.

`scope()` возвращает то, что вернул колбэк, и в любом случае сбрасывает
вложенный контекст — ошибка внутри никогда не подменяется ошибкой очистки.
При успехе проверяется контекст, который открыла эта область, и только он:
внешний контекст всё ещё выполняется, и не удовлетворённое пока ожидание теста
вложенной области не касается. За тест целиком отвечают `verifyAll()`,
`checkpoint()` и teardown адаптера раннера.
Созданный в области дубль после её закрытия недействителен. Настраивать и
проверять дубль можно только в контексте-владельце; обычный вызов допустим из
другого Fiber и всё равно записывается в лог владельца.
`checkpoint()` сохраняет дубли, их режимы и метки, очищая то, что текущая фаза
уже завершила.

### Чтение лога вызовов

```php
use Rasuvaeff\Understudy\Arg;

$calls = Understudy::calls(fn () => $repository->find(Arg::any()));

$calls[0]->args;          // [123]
$calls[0]->didReturn();   // true
$calls[0]->returned();    // чем ответил
$calls[1]->thrown();      // исключение, если бросил
```

`null` — полноценное возвращаемое значение, поэтому об исходе спрашивают
(`didReturn()`), а не выводят его из самого значения.

```php
$last = Understudy::lastCall(fn () => $repository->find(Arg::any()));

$last?->args;   // самый поздний совпавший вызов, null, если вызова не было
```

`lastCall()` — null-safe замена `count($calls) - 1`: у пустого лога нет
последнего элемента, и статический анализ это не может опровергнуть, поэтому
арифметика индексов даёт `int<-1, max>` ещё до запуска теста.

### Забывание заменённого дубля

```php
Understudy::forget($replaced);
```

Для дубля, который тест создал, а потом заменил — `$this->generator =
$this->fixedGenerator('other')` оставляет первый позади, со всеми его стабами.
Под `verifyAll(strictStubs: true)` такой стаб — ошибка о дубле, которым тест
больше не пользуется; `forget()` выводит его из игры: верификация, учёт и
reset его больше не видят. Любой вызов на объекте после этого — как и вопрос
о его вызовах — падает с `ForgottenDouble`, где назван `forget()`, а не
отправляет искать несуществующий `reset()`. В одну сторону, как и любое
забывание здесь.

### Режимы

| Режим | Чем отвечает несовпавший вызов |
|---|---|
| Loose (по умолчанию) | типобезопасным значением: `null`, `0`, `''`, `[]`, пустой генератор … |
| Strict (`Understudy::strict($double)`) | немедленной ошибкой с именем метода, самим вызовом и тем, что его не приняло |
| Forwarding (`Understudy::forwarding($double, $real)`) | тем, что ответит реальный инстанс — с записью вызова, как любого другого |

Loose-дубль никогда не выдумывает значение, запуская чужой конструктор, и
никогда не отдаёт экземпляр настоящего класса с пропущенным конструктором.
Отдать он может другой дубль: возвращаемый тип, который сам можно дублировать,
становится дублем — на один уровень, и тот же тест может его настроить. Это
сгенерированный заменитель, а не цель с пропущенным конструктором.

Ровно один уровень: созданный так дубль откажется породить следующий, поэтому
`$a->b()->c()` скажет об этом, а не выдумает третью зависимость, о которой тест
не просил. Зарегистрировать фабрику для `C` — способ сказать, что вы этого
хотели. Если безопасного значения нет — он говорит об этом и подсказывает выход.

### Как сказать, каким должен быть дефолт

Вложенный дубль `LoggerInterface` отвечает на всё дефолтами и не сообщает тесту
ничего. Обычно нужен `NullLogger`:

```php
Understudy::defaults(LoggerInterface::class, fn () => new NullLogger());
Understudy::defaults(ClockInterface::class, fn () => FakeClock::frozen());
```

Регистрация выигрывает у `null` на nullable-возврате: метод, объявленный
`?ClockInterface`, отвечает зарегистрированными часами — сказать, чем должен
быть тип, значит сказать это и здесь. Без регистрации такой метод по-прежнему
отдаёт `null`.

Побеждает ближайшая регистрация — по расстоянию в графе типов: сначала точное
совпадение, затем ближайший зарегистрированный предок. Два предка на одинаковом
расстоянии дают `AmbiguousDefaultFactory`, а не «кто раньше зарегистрировался» —
у ничьей нет порядка, который читатель мог бы предсказать. Фабрика, вернувшая не
тот тип, даёт `InvalidDefaultValue`.

Регистрации принадлежат текущему контексту: соседние Fiber'ы не видят чужих, а
`Understudy::reset()` удаляет их вместе с тестом. Регистрировать их следует в
per-test фикстуре, а не один раз на весь suite.

### Сборка тестируемого объекта

```php
['sut' => $service, 'doubles' => $d] = Understudy::wire(CatalogService::class);

/** @var Repository $repository */
$repository = $d['repository'];
when(fn () => $repository->find(1))->returns($book);

Assert::same($service->lookup(1), $book);
```

`wire()` читает конструктор и больше ничего: ни контейнера, ни инъекции в
свойства, ни сеттеров. Юнит-тесту важны те зависимости, о которых класс просит
сам.

| Параметр конструктора | Что получает |
|---|---|
| класс или интерфейс | дубль, попадает в `doubles` под именем параметра |
| nullable-объект | дубль — `null` тест может попросить явно |
| пересечение типов | один дубль обоих контрактов |
| union из нескольких объектных типов | отказ: выбрать один значило бы угадать |
| объект, который нельзя дублировать, с дефолтом | собственный дефолт, применённый PHP |
| скаляр с дефолтом | объявленный дефолт, без дубля |
| скаляр без дефолта | отказ с указанием, какой override передать |
| вариадический хвост | остаётся пустым; выдумать элементы значило бы выдумать зависимости |
| параметр по ссылке | отказ — override'ы это значения, и передать их значило бы пообещать reference-семантику, которой у `wire()` нет |

`overrides: ['name' => $value]` подменяет одну зависимость реальным объектом или
готовым дублем; они уже у вас в руках, поэтому в `doubles` не попадают. Любой
отказ происходит до вызова конструктора — неверный тип сообщает `wire()`, а не
`TypeError` изнутри тестируемого объекта.

Вариадический хвост принимает список, и каждый элемент проверяется против
объявленного типа до вызова конструктора:

```php
['sut' => $service] = Understudy::wire(TaggedService::class, ['tags' => ['a', 'b']]);
```

Всё, что не список — голое значение, массив со строковыми ключами, — отвергается
с указанием имени, как и элемент неверного типа. Заполнение хвоста означает, что
параметры перед ним передаются позиционно, поэтому пропущенный опциональный
параметр получает материализованный объявленный дефолт; это единственное место,
где `wire()` вычисляет дефолт сам, а не оставляет его PHP.

### Делегирование реальному объекту

```php
$real = $container->get(CacheInterface::class);
$spy = Understudy::for(CacheInterface::class);
Understudy::forwarding($spy, $real);

when(fn () => $spy->get('key'))->throws(new PoolOverload());
```

Всё, что тест не настроил, выполняется по-настоящему и записывается; `get('key')`
бросает. Инстанс обязан удовлетворять всем контрактам дубля, иначе отвергается.

`Understudy::delegate()` — эта пара одним выражением: строит дубль, включает
делегирование и возвращает дубль —

```php
$spy = Understudy::delegate(CacheInterface::class, $real);
```

`Understudy::for($real)` — сокращение для не-final класса: строит дубль класса
этого объекта и запоминает сам объект, но продолжает отвечать дефолтами, пока
`Understudy::forwarding($double)` не включит делегирование. Обернуть — не то же
самое, что делегировать. Final-класс отвергается: он уже загружен, и дубль не
сможет сохранить конкретный тип, который вы держите в руках.

Внутри ответа один вызов можно пропустить наружу:

```php
when(fn () => $spy->get('key'))
    ->answers(fn (Invocation $call) => strtoupper((string) $call->callOriginal()));
```

Пять вещей, которые стоит знать заранее:

- **Записывается только вызов на границе.** Если реальный метод зовёт другой
  метод на себе, это происходит внутри реального объекта. Understudy проксирует
  объект, а не инструментирует его.
- **Метод с `: never` доходит до реальной реализации.** Бросок живёт именно
  там, а у forwarding-дубля есть кому ответить за себя.
- **Дубль не может быть целью.** Делегирование дублю — в том числе самому себе —
  возвращает каждый вызов обратно в диспетчер, и несовпавший будет возвращаться,
  пока не кончится стек.
- **Аргумент по ссылке — это переменная вызывающего.** Форвардящийся метод в
  неё пишет, и журнал хранит оба чтения — что передали и чем оно стало, — так
  что проверка по-прежнему видит значение, которое отдал вызывающий.
- **Fluent-метод возвращается дублем.** Когда реальный инстанс вернул сам себя,
  наружу уходит дубль — цепочка остаётся дублированной. Метод с `static`,
  вернувший *другой* экземпляр реального класса, отвергается: этот объект не
  дубль, и вернуть его значило бы нарушить собственный `: static` переопределения.

### Сообщения об ошибках

```text
Understudy `BookRepository` expected `tag('alpha', 2)` to be called exactly 1 time,
but it was never called.

The following calls to `tag` were made during this test:
    tag(*'beta'*, 2)
```

Звёздочками помечен разошедшийся аргумент — приём заимствован у
[NSubstitute](https://nsubstitute.github.io). `Understudy::label($double, '…')`
даёт дублю имя, когда их в тесте несколько на один контракт.

Объектный аргумент сравнивается по идентичности, поэтому два экземпляра не
совпадут, как бы одинаково они ни читались, — и сообщение обязано показать,
какая из двух причин сработала:

```text
Understudy `BookRepository` expected `save(App\Book#1 {title: 'Dune'})` to be called
exactly 2 times, but it was called 1 time.

The following calls to `save` were made during this test:
    save(App\Book#1 {title: 'Dune'})
    save(*App\Book#2 {title: 'Dune'}*)
```

`#1` и `#2` — псевдонимы, нумерация идёт внутри одного сообщения в порядке
первого появления: один и тот же экземпляр везде сохраняет свой номер, поэтому
строка выше говорит «это тот объект, который вы назвали», а помеченная —
«это пересобранная копия». Это не идентификаторы объектов: id переиспользуется
после сборки мусора, и один и тот же падающий тест печатал бы разные числа на
разных прогонах.

В фигурных скобках — **публичные** свойства, до пяти, с тем же бюджетом
вложенности, что и у остального сообщения. Ради их печати ничего не
вызывается: объект, который держит состояние за геттерами, рендерится одним
псевдонимом — запускать геттер, чтобы напечатать сообщение, значило бы
исполнить тестируемый код в самый неподходящий момент.

Strict-дубль отказывает на самом вызове, а не в teardown, и говорит, с чем он
этот вызов сравнивал:

```text
Understudy `BookRepository` is strict and received an unexpected call to `tag()`.

The call was:
    tag('beta', 1)

Nothing configured for `tag` accepted it:
    tag(*string(matches: /^a/)*, *2*)

Configure it first: when(fn () => $double->tag(...))->returns(...)
```

Пометки читаются со стороны ожидания: каждая — аргумент, который отверг этот
вызов, включая позицию, которой в вызове не было вовсе. Перечисляется всё
настроенное для метода — в том порядке, в котором их перебирает диспетчер, до
пяти, дальше счётчик: стаб, который не мог совпасть в принципе, часто и есть
тот, который тест собирался написать. Когда для метода не настроено ничего,
сравнивать не с чем — сообщение остаётся одной строкой с именем метода.

Сообщение написано для человека, и его формулировка в публичный контракт
пакета не входит: патч-релиз вправе переписать текст. Всё, что действует по
ошибке, а не печатает её — адаптер раннера, плагин IDE, агрегатор отчётов, —
читает `VerificationFailed::failures()`: кейсы `FailureKind` и readonly-поля
`VerificationFailure` заморожены как публичный API с v0.1.0. Тест, который
ассертит точный текст сообщения, ассертит прозу.

### Очистка

```php
Understudy::reset();
Understudy::idle();   // true, если в текущем контексте нет ни одного дубля
```

Адаптеры [understudy-testo](https://github.com/rasuvaeff/understudy-testo) и
[understudy-phpunit](https://github.com/rasuvaeff/understudy-phpunit)
проверяют и сбрасывают контекст после каждого теста сами; без адаптера —
вызывайте `reset()` в своём teardown. Изоляция и учёт — разные вещи: у каждого
Fiber своя фаза записи, свой лог вызовов и свой счётчик последовательности, но
`verifyAll()`, `reset()`, `idle()` и `checkpoint()` охватывают все контексты,
куда тест положил дубли. Тело, исполняемое в Fiber, — всё ещё этот тест, а
адаптер спрашивает про тест оттуда, где стоит сам.

### Использование Pest

Pest уже занимает глобальную функцию `expect()`, поэтому импорт глагола
настройки understudy с ней конфликтует. Импортируйте функцию под другим
именем:

```php
use function Rasuvaeff\Understudy\expect as expectCall;

expectCall(fn () => $books->find(7));
```

или используйте везде бесколлизионную статическую форму:

```php
Understudy::expect(fn () => $books->find(7));
```

`when()` и `verify()` глобально свободны и в алиасе не нуждаются.

## Безопасность

Understudy генерирует по классу на набор контрактов и вычисляет его один раз
за процесс. Она не загружает код из пользовательского ввода, не обращается к
файловой системе и держит всё состояние в `WeakMap` по ключу-объекту — а не по
`spl_object_id()`, который PHP переиспользует после сборки мусора.

Это dev-зависимость. В production её ставить не нужно.

Исполняемые скрипты — в [examples/](examples/), по одному на концепцию: три

## Разработка

```bash
make build          # validate, normalize, require-checker, cs, psalm, test
make cs-fix
make psalm
make test
make mutation       # infection, гейт 92% MSI
make release-check

make perf-install   # один раз: сравнительный харнесс в perf/
make perf           # против Mockery, Prophecy и PHPUnit
make perf-cold      # холодный старт, один процесс на дубль
make perf-memory    # память на живой дубль
```

Или напрямую через Docker:

```bash
docker run --rm -v "$PWD":/app -w /app composer:2 composer build
```

В `spikes/` лежат feasibility-фикстуры, на которых стоит дизайн; `bash
spikes/run.sh` прогоняет их на любом PHP 8.3+.
